# AIofCage 决赛演示路线与交付对照

> 版本：v1 · 2026-10-30
> 依据：《评审演示与体验验收手册 v2.0》§3 的 10 分钟时序 + 初评反馈三条 + 《同议题项目审阅》§7
> 原则：**只走一条用户路径，不做功能巡游。**

---

## 0. 一句话

10 分钟只证明一件事：

> **同一个项目里，Agent 能干完活，也能被关住，而且每一步都留得下证据。**

## 2. 五个优化项落在哪一段

| 优化项 | 落在 | 为什么在这里 |
|---|---|---|
| **① 权限粒度分离 + 真实远程 MCP** | 5:30–6:30 安全 | 唯一一段"证明关得住"，也是议题硬要求 |
| **② 预构建镜像 + DMG + Release** | 2:00–3:00 准备 | 这一段决定"普通用户能不能开始" |
| **③ 兼容矩阵** | 7:00–8:00 价值 + 备用页 | 回答"支持到什么程度"，不占主讲时间 |
| **④ 项目边界说明 + 退出检查** | 1:00–2:00 边界 / 4:30–5:30 成果 | 先说清边界，再展示成果，顺序不能反 |
| **⑤ 运行状态诚实化** | 2:00–3:00 / 6:30–7:00 | 应用退出 ≠ VM 停机 ≠ 任务结束 |

## 3. 逐段操作脚本

### 0:00–1:00 · PPT 定位

**说**：
> "现在让 Agent 干活，等于把家门钥匙交给一个可能被网页骗的人。我们做的是：让它在笼子里干，钥匙不进笼子，出事能查。"

**不出现**：MITM、namespace、cgroup、CA、占位符。

---

### 1:00–2:00 · 边界 → 进项目

**PPT**：三层边界一张图（文件 / 网络 / 凭证），每层标"谁持有"。

**切 App**：点进演示项目，停在工作台。

**说**：
> "文件：Agent 只看得到这个项目目录。网络：只有一条出网的路，走门卫。凭证：真 key 只在钥匙串和门卫内存里，Agent 手里是占位符。"

**必须主动补一句**（对应优化项④）：
> "注意：当前 Agent 直接写这个项目目录，不是副本。所以我们在退出时检查 `.claude/`、`.git/hooks` 这类配置有没有被改。副本+回写闸门在路线图上。"

**验收**：切屏后仍停在同一个项目；不打开任何含私人内容的 Finder 目录。

---

### 2:00–3:00 · 准备 / 工作台

**操作**：选 Agent（Codex）→ 选供应商/模型 → 启动。

**说**：
> "环境是预构建的，第一次用要下载，之后走缓存。每个阶段是真的，能取消。"

**必须成立**（对应优化项②⑤）：
- 显示真实阶段：检查 → 下载 → 校验 → VM 启动 → 镜像 → 门卫就绪
- 有总量才画百分比，没有就显示阶段名
- 任意阶段可取消，退出后无残留进程
- **不出现**"检查专用虚拟机/构建镜像"这种一句话糊过去的提示

**验收**：3 分钟内进入可输入状态；点取消能真的停。

---

### 3:00–4:30 · 任务

**操作**：填入准备好的短任务 → 确认发送 → 展示工具活动 → 中途点一次停止（再继续或重发）。

**说**：
> "这是真实的工具调用，不是回放。"

**验收**：4:30 前出现第一个真实产物；停止按钮始终可见。

---

### 4:30–5:30 · 成果

**操作**：点产物 → 打开真实文件（Finder 或编辑器）→ 跑一次检查。

**说**：
> "打开的是真实文件。运行完成不等于结果正确，所以我们单独展示检查结果。"

**必须区分**：新产物 vs 历史文件；"任务完成" vs "检查通过"。

---

### 5:30–6:30 · 安全（全场最重要 60 秒）

**操作 A（拒绝）**：触发一次非白名单域名请求 → 面板出现红色事件 + 原因 + 作用域选项。

**操作 B（撤销）**：进工具权限页 → 撤销某个 MCP 工具授权 → 让 Agent 再调一次 → **失败**。

**说**：
> "我们授权的不是连接，是能力。远程 MCP 按 tool / 方法+路径授权，数据库按 verb + 表授权——两套粒度在同一个页面里区分得开。"

**必须成立**（对应优化项①）：
- 用的是**真实远程 MCP**，不是只读合成案例
- 撤销后**当场失败**，并有审计记录
- 不用"数据库只读"冒充"全部远程工具受控"

**红线**：不通过放宽权限救场。

---

### 6:30–7:00 · 证据

**操作**：从刚才那条拒绝事件，直接跳到同对象的审计与用量。

**说**：
> "审计和用量都对到同一个任务上。用量如果拿不到精确归属，我们会标'沙箱范围'，不填零。"

**必须成立**（对应优化项⑤）：应用退出、VM 停机、任务结束三种状态分开表述。

---

### 7:00–8:00 · PPT 价值

**说**：
> "目标用户是三类人：在 Mac 上用 Codex/Claude Code 的开发者；不想把 key 发给成员的小团队；有合规要求的金融政企。我们卖的不是隔离强度，是'密钥边界可见、可撤销、可审计'。"

**备用页**：兼容矩阵（Agent × 服务 × 认证 × 传输），每格标"已验证 / 未验证 / 不支持"。

---

### 8:00–9:00 · PPT 工程

**列**：真实 PR 清单、每个功能的验证记录、AI 参与的环节（哪一段是 agent 写的、人改了什么）。

**说**：已实现与路线图分开，不混。

---

### 9:00–10:00 · 缓冲

不新增流程。准备三个问答过渡句。

## 5. 彩排检查点（11-02）

| 检查 | 通过标准 |
|---|---|
| 总时长 | ≤10 分钟，不留到 10:30 |
| 点击/切屏数 | 记录，尽量 ≤15 次 |
| 等待时间 | 最长一次 ≤20 秒，超了要提前预热 |
| 失败分支 | 至少演练：网络断、模型超时、产物未生成 |
| 切屏 | 切回 App 仍停在目标项目 |
| 投影 | 真实分辨率下正文可读，不溢出 |

---

## 6. 故障分支

| 现场情况 | 处理 | 必须说明 |
|---|---|---|
| 短时间无输出 | 看真实活动状态，按时间窗决定继续或停止 | 没输出不等于死锁 |
| 模型/网络不可用 | 显示错误 → 切录屏 | "这是此前录制的，版本与日期可查" |
| 任务失败 | 保留错误与已有改动，展示重试入口 | 失败不能讲成完成 |
| 产物未生成 | 明确未完成 | 历史文件不能冒充本轮产物 |
| 安全探针条件不足 | 保留"无法验证" | 不改判定救场 |
| 新功能没做完 | 从现场链路移除 | 设计稿和实录要分清 |

## 9. 产品化 = 商业化（50% 权重的真实落点）

评委打"商业价值与产品设计"分，看的不是商业模式画布，是**普通用户能不能自己开始、能不能感知进度、能不能信任结果**。所以进度条、DMG、预构建镜像不是"打磨细节"，它们就是这 50 分的实体。

### 9.1 六个产品化项

| 项 | 现状 | 目标 | 验收 | 商业含义 |
|---|---|---|---|---|
| **进度条** | 一条"构建镜像"提示 | 6 个真实阶段（检查→下载→校验→VM 启动→镜像→门卫就绪）+ 有总量才画百分比 + 任意阶段可取消 | 3 分钟内进入可输入状态；取消后无残留进程 | 首次成功时间（TTFV）决定留存 |
| **DMG** | 需源码构建 | 签名 + DMG + GitHub Release + README 改成"下载即用" | 另一台 Mac 双击打开，全程不出现 Go/Node/Docker 命令 | 安装门槛 = 获客门槛 |
| **预构建镜像** | 现场 build | 预构建 + 摘要校验 + 缓存命中 + 本地回退 | 二次启动 ≤30 秒；摘要不符拒绝启动 | 每次使用成本决定复购 |
| **首次引导** | 已有（被评委表扬） | 三步：选目录 → 选 Agent → 开始；空状态各一句 | 新用户 3 步内发出第一个任务 | 新手转化率 |
| **错误可解释** | 分散在各处 | 错误码 + 原因 + 就近重试入口 | 任意失败都能说清"下一步点哪" | 支持成本 |
| **产物直达** | Finder 打开 | 一键打开真实文件 + 单独展示检查结果 | 4:30 前能打开产物并核对 | 价值感知 |

### 9.2 三个可量化的指标（写进 PPT 备用页）

| 指标 | 定义 | 目标 |
|---|---|---|
| **首次成功时间** | 从下载 DMG 到第一个任务完成 | ≤10 分钟 |
| **冷启动时间** | 缓存命中后，点启动到可输入 | ≤30 秒 |
| **失败可恢复率** | 演示中 3 类错误里，用户能自己恢复的比例 | 3/3 |

> 四类启动指标（首次安装 / 冷启动 / 缓存 / 运行）分开记，不混成一个数。

### 9.3 商业化叙事（不报 TAM）

> **企业分发的是用量，不是 key。**

- 个人版免费
- 团队版按席位：集中托管 key、统一下发白名单与 MCP 策略、按人设额度、导出审计
- 企业版：门卫 + 管理台部署内网，对接 SSO / SIEM

三条护城河，全部来自产品化：

1. **一个入口管三种 Agent**（不是三个工具）
2. **普通人不学 Docker 就能用**（DMG + 预构建 + 引导）
3. **密钥边界可见、可撤销、可审计**（不是黑盒）
