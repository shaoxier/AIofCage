# 供应商模型列表验证

[验收记录索引](README.md)

## 改动

对应第二轮会议第 5 条和 [todo 清单](../round2/todo.md)第 5 项。

1. **公共的取模型函数**（`internal/service/models.go`）：
   - 按协议请求 `/models`：OpenAI 兼容接口是 `<地址>/models`；Anthropic 是 `/v1/models`，按 `has_more` 翻页，最多 5 页。后面的页失败时，保留前面取到的模型，并说明“列表没有读完”。
   - 解析 `data[].id`：只保留保存供应商时也接受的名字（字母、数字或 `@` 开头，其余是字母、数字和 `. _ : / @ + -`，最长 200），去重，最多 500 个，按名称排序。列表里能选的名字都能保存。
   - 失败时分类说明：密钥无效、没有模型列表接口、被限流、返回为空、格式无法识别、读取超时、连不上（附原因）、服务返回跳转。每种情况都提示可以手动填写模型名称。
   - 只请求供应商自己的地址，不跟随跳转。
   - “测试连接”和终端刷新都改用这个函数。“测试连接”的结果含义不变，成功时多显示取到几个模型。
2. **两个新接口**：
   - `ProviderModels(id, refresh)`：用于已保存的供应商；
   - `PreviewProviderModels(request)`：用于保存之前，可以用表单里填的 key、预设里的钥匙串条目，或者编辑时已保存的 key。只接受预设里列出的钥匙串条目，而且只发往预设的地址；供应商自己的条目只能经由已保存的供应商使用。表单里填的 key 只用这一次，不保存也不缓存。
3. **缓存 20 分钟**：
   - 缓存成功的结果，以及“没有模型列表接口”（404、405），免得每开一个终端标签都问一次；其他失败不缓存。缓存键是“地址 + 协议 + 认证方式 + 钥匙串条目”，不含 key 本身。
   - 保存或删除供应商时，清掉用到它的钥匙串条目的缓存。清除之前已经发出、清除之后才返回的请求，结果不进缓存，所以换 key 后不会读到用旧 key 取的列表。
   - 终端刷新和“测试连接”都会更新这份缓存。
4. **供应商表单**：
   - 模型一栏改成可以搜索的下拉，也可以直接填写，旁边有“获取模型列表”按钮。
   - 回车：用方向键选中某一项后，回车换成这一项；没有选中时保留手填的名称，表单照常提交。Esc 只收起下拉，不关闭对话框。
   - 下拉最多显示 50 项，更多时底部提示“还有 N 个，请输入名称筛选”。
   - 地址固定的预设，填好 key（或选用钥匙串里的条目）后自动获取。自定义地址要用户自己点按钮，免得把 key 发给还没填完的域名。
   - 换预设，或者改了地址、协议、认证方式、key，旧列表立即清空，还没返回的请求作废。
   - 编辑已有供应商时，先显示缓存的列表；没有缓存时，用已保存的地址和 key 获取一次。
   - 选回同一个模型不会清掉已填的单价，换了模型才清。
5. **终端**：
   - 模型输入框换成同一个下拉。打开会话时读一次缓存的列表（没有缓存才请求），刷新按钮重新获取并更新同一份缓存。
   - 供应商配置的模型始终在列表里，换了别的模型也能换回来。
   - 打开时读取失败不提示，照常手动填写；点刷新失败时才说明原因，并保留原来的列表。
   - 换成供应商单价所配模型以外的模型时，提示“用量照常统计，但不估算费用”。

## 自动测试

- `internal/service`：
  - OpenAI 格式：过滤不合法和重复的名字、请求头带 key、第二次读缓存、刷新重新请求、保存供应商后缓存失效；
  - Anthropic 格式：带 `limit` 翻页，带 `x-api-key` 和 `anthropic-version`；第 2 页失败时保留第 1 页的模型；
  - 401、404、空列表、格式错误、跳转：都有对应说明，跳转不跟随；404 记住，其他失败下次重新请求；
  - 列表里的名字都能保存：`@cf/meta/llama-3-8b-instruct`、`org/model+beta`、`qwen:72b`、200 个字符的名字；
  - 取列表期间清除了缓存（换 key），结果不进缓存。去掉这个判断后测试失败，确认测试有效；
  - 保存前获取：用表单里的 key；预设的钥匙串条目不会发往别的地址，那次请求根本没有发出；没有 key 时提示先填；供应商自己的钥匙串条目不能直接拿来预览，请求没有发出。
- 原有的“测试连接”测试（不跟随跳转、预设 key 不发往别的地址、结果分类）照常通过。
- 前端：模型筛选（开头匹配优先、完整名字时列出全部）、超过 50 个时的剩余数、供应商配置的模型放在列表最前面。
- `make check`、`make test`（含竞态检查）、前端 `node --test` 都通过。

## 真机验证（2026-10-30）

- **真实供应商**：用本机已配置的四个供应商走 `ProviderModels`：
  - 七牛 xapi：取到 5 个模型（gpt-5.6-sol、gpt-5.6-terra、gpt-6-astra、gpt-6-sol、gpt-6.1-sol），第二次读取命中缓存；
  - DeepSeek 的 OpenAI 兼容接口：取到 2 个模型（deepseek-flash、deepseek-v4-pro）；
  - DeepSeek 的 Anthropic 兼容接口：返回 404，提示“服务可达，但不提供模型列表接口，请手动填写模型名称”。
- **供应商表单**（模拟后端）：
  - 选七牛 xapi 预设后填 key，0.7 秒后自动获取一次（连续输入 21 个字符只发一次请求），显示“连接正常，取得 5 个模型”；改一个字符后列表清空，0.7 秒后重新获取；
  - 输入 “gpt-6” 时下拉列出 3 项、没有选中项；按两次下方向键再回车，换成 gpt-6-sol，表单没有提交；
  - 输入 “model-01” 直接回车，保存请求里的模型就是 “model-01”；
  - 120 个模型时显示 50 项，底部提示“还有 70 个，请输入名称筛选”；用上方向键选中第 50 项，它没有被提示挡住；
  - 下拉展开时按 Esc，只收起下拉，对话框和已填内容都在；
  - 让获取延迟 1.5 秒，期间改了地址：列表立即清空，1.5 秒后返回的旧结果被丢弃；
  - 自定义地址：填完地址和 key 不会自动请求，点“获取模型列表”才请求一次。
- **终端**（模拟后端，供应商不提供列表接口）：
  - 打开会话时读取一次（不强制刷新），失败不显示提示，下拉里有供应商配置的模型；
  - 点刷新返回 401 时显示“密钥无效或没有权限”；再刷新取到 3 个模型；之后刷新被限流时显示限流说明，3 个模型仍在。

## 独立复查

请子代理在独立工作树里只读复查了一轮，用探针测试复现问题，没有用真 key、没有请求真实服务。结论是没有把 key 发到不该去的地方的高危问题，有 3 个中等、6 个低：

| 级别 | 问题 | 处理 |
|---|---|---|
| 中 | 回车总是换成列表第一项，手填的名称或当前模型被替换 | 只在方向键选中后才拦截回车 |
| 中 | 终端打开会话时从不读缓存的列表 | 改用专门的标记，只在打开时读一次 |
| 中 | 列表里的部分名字（`@` 开头、带 `+`、超过 128 字符）保存时被拒 | 列表和保存用同一条规则，并放宽到 200 字符 |
| 低 | 选回同一个模型会关掉单价，保存时单价被删 | 值没变就不通知；换了模型才清单价 |
| 低 | 换 key 前发出的请求，结果在清除缓存后写回 | 按钥匙串条目计数，清除后返回的结果不缓存 |
| 低 | 换预设、地址后仍显示旧列表；编辑时的初始读取会覆盖后来的结果；认证方式不触发自动获取 | 这些变化都清空列表、作废请求；认证方式加入自动获取的条件 |
| 低 | Anthropic 后面的页失败时丢掉前面的结果；正文读取超时被说成格式无法识别 | 保留已取到的模型；超时单独说明 |
| 低（纵深防御） | 预览时可以直接指定任何供应商自己的钥匙串条目，发往任意地址 | 预览只接受预设条目 |
| 低 | 超过 50 个时没有提示；终端刷新失败会清空列表 | 加剩余数提示；失败时保留原列表 |

另外，“没有列表接口”的结果原来不缓存，终端每开一个标签都会请求一次并提示，现在会记住。自测时又发现：下拉展开时按 Esc 会把整个供应商对话框关掉，已改为只收起下拉。修复后没有再请子代理复查，逐条用上面的自动测试和模拟界面验证。

## 范围与限制

- **没有模型列表接口的服务**：例如 DeepSeek 的 Anthropic 兼容接口，只能手动填写模型名称。
- **换模型后不估价**：只给出提示，没有做按模型配置单价。
- **缓存只在内存里**：重新打开应用后，第一次会重新请求。
- **应用外改了 key**：用 `cagectl` 或钥匙串访问修改钥匙串条目时，桌面应用不知道，最长 20 分钟内仍显示用旧 key 取到的列表。影响只是列表可能过期，点刷新即可更新。
- **编辑时改了地址**：编辑已保存的自定义供应商并改了地址，点“获取模型列表”会用已保存的 key 请求新地址，和保存后“测试连接”的行为一致。预设的钥匙串条目仍只发往预设地址。
