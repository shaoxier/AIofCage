# 会话附件支持任意文件

[验收记录索引](README.md)

## 背景

对话页改版时，用户要求输入框左下角的“+”不只加图片，也能加文件。以前只收 PNG、JPEG、GIF、WebP 四种图片，其他文件会被拒绝。

## 改动

后端：

- `internal/service/terminal_images.go`：前端发来的附件多了可选的 `name`。按内容判断：能完整读出的四种图片照旧交给 CLI 识图（含 dsh 的图片能力检查）；其余都当普通文件。每次最多 4 个附件、每个 10 MB、合计 20 MB，空文件不能发送。
- `internal/runtime/terminal_images.go`：`AttachmentName` 清理文件名，只留最后一段；路径分隔符、控制字符、看不见的格式字符、无效编码和 shell 特殊字符换成下划线；只剩点和空格时用“附件”；超过 120 字节时截断，并尽量保留扩展名。文件写到 `/home/agent/.aiofcage/attachments/<批次>/<序号>-<名称>`，图片仍是 `<序号>.<扩展名>`。
- 写入脚本 `terminal-images.py` 改为直接以智能体用户（1000:1000）运行：`docker exec --user 1000:1000 --workdir / … /usr/bin/python3 -I`，不再经过 `aiofcage-run`。原来那一层会加载智能体能改写的 `~/.aiofcage/env`，Python 也会从智能体可写的项目目录导入模块。脚本不跟随 `~/.aiofcage`、`attachments` 和批次目录上的链接；批次目录每次新建并确认是空的；每个文件只在不存在时创建，写完核对类型、大小、权限和链接数。写到一半失败时删掉已写的部分；删除只删符合命名格式的条目，不跟随链接。
- `internal/service/conversations.go`：普通文件的沙箱路径附在消息后面交给智能体，格式是“附件（已复制到沙箱，可直接读取）：”加每行一个用单引号括起来的路径；没写文字时补一句“请查看这些文件。”或“请查看这些图片和文件。”。会话事件只带图片数和清理后的文件名，不带内容和路径。附件批次在关闭会话时删除，和以前的图片一样。

前端：

- `terminal-draft.js`：草稿里的 `images` 改名为 `attachments`，任意文件都能加；只有四种图片生成预览，发送时带上文件名。
- `composer.js`：“+”菜单改成“添加照片和文件”，文件选择框不再限制类型；附件区图片显示缩略图，其他文件显示文件图标、文件名和大小；提示改成“3/4 个附件 · 图片需所选模型支持”（只有图片时才提模型）。
- `terminal.js`、`sandbox-detail.js`：粘贴和拖入都接受任意文件；只有粘贴单张 TIFF（截图）时，照旧由后端读剪贴板转成 PNG。拖入提示改成“松开以添加附件”。
- `conversation-view.js`、`conversation-state.js`：你的消息里显示“1 张图片”和每个文件名。

## 实测

### 自动测试

- `go test -race ./internal/service/... ./internal/runtime/...` 通过。
- 写入脚本另有 9 个 Python 用例（从 Go 测试里跑）：预先放好的符号链接和硬链接、已存在的批次目录、恶意负载、写到一半失败、安全删除。把脚本里的链接防护去掉后有 3 个用例失败，说明能拦住回退。
- `AttachmentName` 跑了约 100 万个模糊输入，清理规则没有被突破，清理两次结果不变。
- 前端 `node --test` 40 项通过，新增任意文件、只给图片生成预览、发送带文件名、大小格式、用户消息记下文件名的用例。

### 真实容器（不调用模型）

`AIOFCAGE_TERMINAL_E2E=1 go test -run TestTerminalImagesEndToEnd ./internal/service/`：建一个临时空白沙箱，写入一张图片和一个名字带路径和空格的文件（`../../季度 报告.txt`），检查字节、权限（文件 600、目录 700）、项目目录不被写入、失败清理和符号链接防护，最后删除沙箱。结果通过（5.8 秒），测试沙箱和网络都没有留下。

## 复查

独立复查（只读代码，另做了 shell 拆分和名称一致性的小实验）没有发现高危问题，确认：写入和删除跑不出沙箱主目录；Docker 调用始终带应用自己的 context，环境变量里的 `DOCKER_HOST`、代理和 `PATH` 被去掉，智能体影响不了 Python 的模块查找；Go 端清理出的名称都能通过脚本的格式检查；大小和数量限制前后端一致；错误和事件里不含内容和路径。指出的问题和处理：

1. 文件名里的空格、方括号、花括号、`~`、`#` 清理后仍保留，智能体不加引号把路径放进命令时会被拆开，例如 `notes [s][r][c]` 会匹配到项目里的 `src`。代码注释和文档原先说“不加引号也安全”，说得过头了。已改为消息里每个路径都用单引号括起来（清理后的名称不含单引号），并改了注释和文档。
2. 从访达复制 HEIC、SVG、BMP 等文件后粘贴，原逻辑会去读剪贴板里的图片，读到的是文件图标。已改为只有粘贴单张 TIFF（截图）时才读剪贴板，其他文件直接当附件，加了用例。
3. macOS 文件名常是分解形式的 Unicode，模型照着重打路径会对不上。名称清理时统一成组合形式，加了用例。
4. 以下保留，记为已知限制：
   - dsh 用的供应商没声明图片能力时，四种常见图片照旧报“未声明图片能力”，不会改当普通文件发送。
   - 附件批次只在关闭会话时删除，应用崩溃或在应用外停掉虚拟机后会留在沙箱主目录；上传超时的极端情况下也可能留下一个批次。这是原有机制，附件内容现在可能是任意文档，需要另做清扫。
   - 损坏或超出像素上限的图片会按普通文件发送；草稿里按文件类型仍显示成图片缩略图，发出后才显示成文件。

## 未覆盖

- Codex 用真实模型读附件：七牛 xapi 当时连不上，待接口恢复后补测。
- 真实应用里点“添加照片和文件”弹出的系统选择框：无法自动操作，用拖入和粘贴覆盖同一条代码路径。
- 其他同样经过 `aiofcage-run` 运行的辅助脚本（例如停止脚本）没有改，存在同样的风险，另行处理。后续已修复，见[应用的辅助命令不再经过 aiofcage-run](2026-11-02-agent-helpers.md)。
