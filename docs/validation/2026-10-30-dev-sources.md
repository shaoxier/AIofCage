# 开发环境与门卫下载修复验证

[验收记录索引](README.md)

## 改动

对应第二轮会议第 7 条（创建沙箱时的开发环境）和 todo 清单第 7 项的最小版本，见[第二轮 todo 清单](../round2/todo.md)。

1. **开发环境预设**（`internal/devsource`）。创建沙箱时或在沙箱设置里选择：
   - npm：不开放、官方源（registry.npmjs.org）、国内镜像（registry.npmmirror.com、cdn.npmmirror.com），三选一；
   - GitHub 只读：克隆公开仓库，下载源码包、Release 文件和原始文件。

   每个预设的规则都是：只放行 GET/HEAD 下载（GitHub 克隆另放行 `git-upload-pack` 的 POST）；发布（PUT/POST 等写方法）和推送（`git-receive-pack`）显式拒绝；请求自带凭据（Authorization、API Key、Cookie）时拒绝。GitHub 的其他页面和 api.github.com 不开放。同时写入客户端设置：npm 的源地址、关闭 audit 和更新提示，`GIT_TERMINAL_PROMPT=0` 让 git 遇到私有仓库时直接报错，不卡在输入密码。运行中修改即时生效。
2. **路径规则支持单段通配**，例如 `/*/*/info/refs`，才写得出 GitHub 克隆的规则。规则可以标成“只允许匿名”。
3. **门卫放行包管理器的正常路径**：允许字面的 `! ( ) * ' [ ]`（Go 模块路径用 `!` 表示大写），以及两种编码，都解码后再匹配规则：任意位置的 `%40`（npm 镜像把 scope 写成 `%40types`），和 scope 包名里的 `%2F`（`/@types%2Fnode`）。其他编码会改变路径的切分方式，仍然拒绝。发往上游的路径保持原样。
4. **跳转**：请求没有注入密钥、跳转目标是 https 443、目标路径也允许 GET 时，原样把跳转交给客户端，由客户端经门卫重新请求、重新检查。304 照常放行。其余跳转拒绝，日志记下跳转目标的域名；带注入密钥的请求被拒时，不向 Agent 透露跳转目标。
5. **看得懂的 403**：状态行改为 `403 Blocked by AIofCage sandbox policy`，正文用中英文说明原因，提醒不要重试或换源，附上请求日志编号；客户端要 JSON 时返回 JSON；响应头带 `X-Aiofcage-Event`。只显示状态行的客户端（git、pip、建立隧道失败时的 curl）也能看出是沙箱策略拦的。

## 复查

### 自查

第一次独立复查因接口额度限流中途退出，我先按威胁模型自查了一遍：

- **路径**：规则按解码后的路径判断，上游收到的是原样写法；双重编码、`..` 段和其他位置的 `%2F` 都被拒绝。
- **跳转**：目标的域名、端口、协议都要检查，并按 GET 重新判断是否允许；注入了密钥的请求不透露跳转目标。
- **拦截提示**：出现的域名都经过校验；HEAD 请求不带正文。

### 独立复查

| 问题 | 程度 | 处理 |

| 设置先保存再下发。下发中途失败时（钥匙串读不到、Docker 查询失败），界面显示已关闭，门卫却还放行；旧版门卫拒收新字段后，之后的撤权（撤销工具、断开 OAuth）也一直下发不了。我自查时的“旧门卫拒收新字段，不会放宽”只看到了第一步 | 中 | 下发失败就让沙箱断网（清空门卫策略，连不上管理接口就停止门卫），下次下发成功或重启后恢复；Docker 查不出状态不当成已停止；旧版门卫给出重启提示；批量刷新不因一个沙箱失败而中止 |

### 修复复查

又请它复查了这批修复。五项都关上了原来的问题，它的复现测试改成了预期结果。它确认了这几点：
- 门卫停了、Agent 还在跑时，重新启动能恢复；
- 不声明的请求 trailer 不会转发给上游；HTTP/2 到不了门卫；
- 常见客户端（npm、git、Codex、Claude Code、pip）都不发请求 trailer；
- 去掉 `X-Aiofcage-*` 头不影响流式回复、304、HEAD 和 MCP 入口。

它又发现 4 个问题，都已修复并补了测试：

| 问题 | 程度 | 处理 |
| --- | --- | --- |
| 刷新拿不到沙箱锁就直接返回，既不下发也不断网。断开 OAuth 时几个沙箱共用一个 30 秒期限，排在后面的沙箱可能一直留着已撤销的授权 | 中 | 可能收紧权限的刷新拿不到锁时，也让沙箱断网；批量刷新给每个沙箱单独两分钟 |

另外两处顺手改进：
- 空策略的版本号跟随门卫当前的版本，宿主时钟回拨也不会被当成过期；
- 旧版门卫的提示里带上原因码。

### 第三轮复查

再请它只看第二轮的修复。

**确认无误的部分：**
- 第二轮的四个问题都已关闭；
- 没有死锁，带 `-race` 的并发复现没有数据竞争；
- 续期失败不会断网，并会重试；
- 不持锁的清空只在沙箱可能在运行时才动手。

**新报的 3 个低危问题。** 都只在两个操作同时改同一个沙箱、而且其中一个占着沙箱超过两分钟（或者登录后下发失败）时才会出现：

| 问题 | 处理 |
| --- | --- |
| 等锁超时后清空门卫，可当时占着沙箱的操作已经下发了正确配置：沙箱多断一次网，也不会自动恢复 | 桌面应用记下刷新失败的沙箱，每分钟按保存的设置补送一次，最多 10 次；成功后断网自动恢复 |
| 清空落在占着沙箱的操作生成配置之前，那个操作随后会重新打开门卫；连接器（PostgreSQL）用的还是它开头读到的旧地址 | 连接器启动前在服务锁下重新读取地址和密码；之后的补送也会按保存的设置纠正。远程和 OAuth 服务本来就在下发时重新读取令牌 |
| OAuth 登录后下发失败不重试；换账号重新登录时，旧账号的令牌还会继续被使用 | 首次登录下发失败时，下一轮检查重试；已有登录时再登录按可能收紧处理，送不到就断网，再由补送恢复 |

它的复现测试只测运行时这一层，所以那两种短暂状态仍能复现；改进在于桌面应用会在下一分钟纠正。

## 范围与限制

- **只放行下载，不防数据外传**：URL 里仍可能夹带数据，包的作者也能看到下载记录。
- **GitHub 只覆盖公开仓库的匿名访问**：私有仓库要凭据注入，留到以后；git LFS 和 api.github.com 不开放。
- **“只允许匿名”只检查请求头**：检查的是 Authorization、API Key 和 Cookie；写在 URL 里的令牌（例如 raw.githubusercontent.com 的 `?token=`）查不出来。这类令牌只能用来读，下载源本身也不放行任何写操作。
- **没有做的部分**：PyPI、Go 模块、crates、Maven 的预设，工具链档位，限时放行，以及给 Agent 的全局说明，都没有做。
- **需要重启沙箱**：已在运行的沙箱要重启一次才换成新门卫。旧门卫不认识新规则字段，给它下发开发环境或远程 MCP 设置时，这个沙箱会暂停联网并提示重启。
- **下发失败就断网**：可能收紧权限的修改（开发环境、MCP 服务与工具授权、编辑或断开服务）送不到门卫时，哪怕只是钥匙串一时读不到、别的操作占着沙箱太久，运行中的沙箱也会暂停联网，要重试或重启才恢复。这是有意偏向安全：门卫不能留着比保存的设置更宽的权限。
- **暂停后的提示不够明显**：暂停后界面仍显示“运行中”，Agent 收到的 403 写的是“不在允许列表里”；暂停的原因只出现在当次操作的报错里。
- **自动补送只在桌面应用里运行**：用 `cagectl` 修改失败时，要自己重新执行；补送最多 10 次，旧版门卫这类不会自己消失的原因要重启沙箱。
- **新旧版本混用会丢设置**：存储层写回时只保留自己认识的字段。升级后如果还用旧版本的应用或 `cagectl` 改同一份数据，会丢掉开发环境和远程 MCP 授权的地址等新字段。
