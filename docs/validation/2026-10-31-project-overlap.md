# 项目文件夹不能重叠验证

[验收记录索引](README.md)

## 改动

[终端文件栏验证](2026-10-31-terminal-files.md)在“范围与限制”里留了一条后续：创建沙箱时没有禁止一个项目放在另一个沙箱的项目里。这次在创建时就禁止，最小版本。

1. **规则**：一个文件夹只属于一个沙箱。新沙箱的项目不能是已有沙箱的项目，也不能在它里面或包含它。
   - 按路径逐段比较，不区分大小写（Mac 默认的文件系统不区分）。结尾斜杠和 `.` 不影响结果，`proj` 与 `proj-2`、`proj2` 不算重叠。
   - 已存在的文件夹再按文件夹本身比较（设备号和 inode），同一个文件夹换一种写法也认得出来，例如名字的另一种 Unicode 写法。本机 APFS 把 `café` 的组合写法和分解写法当成同一个文件夹，只比路径会漏掉。
   - 没有项目路径的记录（测试数据）不参与比较。
2. **检查的位置**：
   - **存储层**：`store.SaveSandbox` 在写入 `sandboxes.json` 的同一把锁里检查，和原来的“已有同名沙箱”一样。这把锁同时管同一进程和不同进程。桌面创建、`cagectl sandbox create`、MCP 案例、本机 AI 控制都经 `runtime.Manager.Create` 走到这里。桌面应用和 `cagectl` 是不同的进程，同时创建重叠的沙箱也只会有一个成功。
   - **桌面“使用已有文件夹”**：准备项目时先查一次，后面的检查不用跑完就能报错。最后以存储层的检查为准。
   - **“新建空文件夹”和“复制到工作区”**：生成文件夹名时，跳过已有沙箱还占着的名字。比如旧沙箱的项目文件夹被删了，但沙箱还在。以前新沙箱会悄悄用上这个路径，旧沙箱再启动就和它共用一个文件夹；现在改用 `名字-2`。
   - 已有沙箱重新保存时（用量、绑定、版本等），只要项目路径没变就不检查，旧数据照常写入。只有换了项目路径才检查。目前代码里没有修改项目路径的地方。
3. **同一个文件夹给多个沙箱**：以前允许，代码里没有任何检查，界面和文档也没提到这种用法。现在也禁止，理由见下一节。想在同一个项目上比较几款智能体，可以把它们装进同一个沙箱，每款智能体各自绑定供应商；也可以选“复制到工作区”另做一份。
4. **提示**（桌面创建对话框和 `cagectl` 原样显示）：
   - 在里面：“这个文件夹在沙箱「X」的项目里面，请换一个与它并列的文件夹”
   - 包含：“这个文件夹里面有沙箱「X」的项目，请换一个不包含它的文件夹”
   - 相同：“这个文件夹已是沙箱「X」的项目，一个文件夹只能给一个沙箱用，请换一个文件夹”
5. **以前已经重叠的沙箱**：启动时拒绝，见“已有沙箱”。

前端没有改动：创建对话框原样显示后端返回的错误（`call` 抛出 Go 的错误文字，对话框 `setError(e.message)`）。

## 为什么要禁止

- **嵌套**：
  - 外层沙箱的 Agent 能看到内层项目这个普通子文件夹，可以改名、删除，换成链接、管道或 `.app`。
  - 宿主上读或打开这个路径的功能会受影响。文件栏和“在访达中显示”已在 PR #77 防住：逐级不跟随链接打开，`open -R` 只显示不打开。
  - 内层沙箱下次启动挂载的是替换后的东西。容器已经存在时，`docker start` 不重新校验项目路径（`ensureObjects` 只在新建 Agent 容器时调用 `ValidateProject`）。按代码推断：外层 Agent 把内层项目换成指向工作区里另一个沙箱项目的链接，内层沙箱再启动就能读写那个项目。这条链路没在虚拟机里复现。
- **同一个文件夹**：
  - 项目根目录本身换不掉：它在容器里是挂载点，改名会失败；它的上一级不在任何容器里，而且 Agent 容器的根文件系统只读。
  - 但两个沙箱可以经文件互传数据和指令。每个沙箱的网络、MCP 工具授权、供应商 key 和额度各管各的；共用一个文件夹，这两套限制就合成了一套。例如 A 沙箱用数据库 MCP 查出的数据，B 沙箱可以读到，再经它自己放行的出口发出去。
  - 两个 Agent 同时改同一批文件也容易互相覆盖。
- 规则成立以后，没有任何沙箱的项目包含另一个项目，项目根目录的上一级不会挂进任何 Agent 容器，Agent 也就换不掉别的沙箱的项目。上面“已存在的容器不复核路径”这个既有行为没有改，但已经不能被 Agent 利用。

## 已有沙箱

- **本机数据（只读）**：
  - 用 `jq` 读 `~/Library/Application Support/AIofCage/sandboxes.json` 的名称和项目路径。这和 `cagectl sandbox ls` 的“项目”列相同；`ls` 还会查容器状态，这次没跑。
  - 开始时有 12 个沙箱，写这份记录时 13 个，中途新建了 `uat-vmgw-old`。
  - 项目都是 `~/CageWorkspace` 下互不相同的一级文件夹，都存在，13 个文件夹的设备号和 inode 也都不同。
  - 逐对比较（不区分大小写）：0 对重叠。本机没有要处理的旧沙箱。
- **处理方式：启动时拒绝并说明**。
  - 位置：`runtime.Manager.startSnapshot` 开头，在检查虚拟机之前。启动、重置后启动、添加或更新智能体后的重启和失败恢复都走这里。
  - 提示：“不能启动：项目文件夹与沙箱「X」的项目重叠（同一个文件夹，或一个在另一个里面），一个沙箱的 Agent 能改动或替换另一个沙箱的项目。请删除其中一个沙箱（项目文件夹会保留），再选一个不重叠的文件夹重新创建”。经现有的操作失败提示显示。
  - 删除沙箱本来就保留项目文件夹，可以选择保留 Agent home。删掉一个以后，另一个就能启动；也可以用原文件夹重新创建。
- **为什么不只在沙箱详情里提示**：
  - 提示拦不住替换以后的再次启动，拒绝启动可以。
  - 一处检查覆盖所有启动路径，也不用改前端。
- **为什么两边都拒绝**：重叠是两个沙箱之间的关系，删掉任意一个，另一个就能启动。只拒绝内层的话，外层照常运行，它的 Agent 仍然能改内层的项目。
- **代价**：已有重叠沙箱的人必须先删掉一个。本机没有，队友的电脑上有没有不知道。
- **不受影响的操作**：保存、查看、删除、打开终端标签和文件栏。升级前已经在运行的重叠沙箱继续运行，直到停止为止。运行中添加或更新智能体时，重启那一步会被拒绝，原沙箱也恢复不了，最后停在已停止状态，提示里带着上面的原因。

## 与 PR #77 的关系

两层防护分工不同：PR #77 在宿主读取、打开项目时设防；本 PR 在创建时就不让项目重叠，从根上去掉“项目被外层 Agent 换掉”这个前提。#77 的两处防护照旧保留，本 PR 没有改动它们的行为。

- **#77 的两处**：
  - **文件栏**：`internal/service/project_files.go` 的 `openProjectRoot` 从 `~/CageWorkspace` 开始逐级 `openat` 打开项目目录，每一级都不跟随链接、非阻塞、必须是文件夹。之后的读取绑定在打开的那个文件夹上。
  - **在访达中显示**：`OpenProjectFolder` 先用同样的方式确认项目目录，再执行 `open -R`，只在访达里选中，不打开。
- **本 PR**：创建时拒绝重叠的项目，以前已经重叠的沙箱不能启动。规则成立后，任何 Agent 都换不掉别的沙箱的项目根目录，#77 防的情形不会再新出现。
- **#77 的防护仍然需要**：
  - 本 PR 不拒绝查看：以前已经重叠的沙箱照样能打开文件栏、在访达中显示，这时靠 #77 的防护。
  - 升级前已经在运行的重叠沙箱继续运行到停止，这段时间里外层 Agent 仍能替换内层项目。
  - 宿主上的其他程序也可能把项目目录换成链接，逐级打开和 `open -R` 对这种情况同样有效。

## 手工验证（cagectl）

在本分支用 `go build` 编出 `cagectl`，没有内嵌 Linux 门卫，创建用不到。`HOME` 指向临时目录，所以存储和 `~/CageWorkspace` 都在临时目录里，没碰本机数据。创建只写元数据，不调用 Docker。路径里的临时目录已替换成 `~`：

```text
$ cagectl sandbox create --name 外层 --project ~/CageWorkspace/proj
已创建沙箱 外层（sbx-tylk52f3），用 cagectl sandbox start 外层 启动
$ cagectl sandbox create --name 内层 --project ~/CageWorkspace/proj/sub
错误： 这个文件夹在沙箱「外层」的项目里面，请换一个与它并列的文件夹
$ cagectl sandbox create --name 同一个 --project ~/CageWorkspace/proj/
错误： 这个文件夹已是沙箱「外层」的项目，一个文件夹只能给一个沙箱用，请换一个文件夹
$ cagectl sandbox create --name 大写 --project ~/CageWorkspace/PROJ/sub
错误： 这个文件夹在沙箱「外层」的项目里面，请换一个与它并列的文件夹
$ cagectl sandbox create --name 深层 --project ~/CageWorkspace/team/api
已创建沙箱 深层（sbx-x5xeo7vk），用 cagectl sandbox start 深层 启动
$ cagectl sandbox create --name 外包 --project ~/CageWorkspace/team
错误： 这个文件夹里面有沙箱「深层」的项目，请换一个不包含它的文件夹
$ cagectl sandbox create --name 并列 --project ~/CageWorkspace/proj-2/
已创建沙箱 并列（sbx-ul3pajto），用 cagectl sandbox start 并列 启动
```

被拒绝的命令退出码为 1，存储里只有“外层”“深层”“并列”三个沙箱。注意 `~/CageWorkspace/PROJ/sub`：在不区分大小写的磁盘上，它能通过原有的 `ValidateProject`（解析链接后路径不变），只比原样路径的话，会创建出一个实际在 `proj` 里面的沙箱。

启动拒绝没有用 `cagectl` 手工试：`cagectl` 优先用 `/opt/homebrew/bin` 里真实的 colima，检查万一没生效，就会在临时 `HOME` 下创建虚拟机。这一项由上面的单元测试覆盖，测试里用的是假 colima。

## 范围与限制

- **不区分大小写的代价**：在区分大小写的卷上会多拒绝一些情况，例如 `Proj` 和 `proj/sub`。提示里写了是哪个沙箱，换个文件夹即可。
- **按文件夹本身比较只对存在的文件夹有效**：已删除的旧项目只按路径比较。项目路径被外层 Agent 换成链接时，按链接指向的文件夹比较，这和启动时实际挂载的一致。
- **没在桌面界面里点过**：创建对话框显示的是后端返回的同一段文字，由单元测试和 `cagectl` 手工验证覆盖。
- **没在虚拟机里复现**：“已存在的容器再次启动时挂载替换后的路径”这一条按代码推断，没有实际复现。
- **没做**：重叠的旧沙箱没有界面提示，也没有一键迁移到新文件夹；这两项要等有人遇到再说。
