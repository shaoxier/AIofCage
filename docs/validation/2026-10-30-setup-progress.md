# 准备环境的进度与停止验证

[验收记录索引](README.md)

## 改动

对应第二轮会议第 6、2 条，以及 [todo 清单](../round2/todo.md)第 6 项的最小组合：只做虚拟机和镜像构建两段的进度、停止和退出收尾。

1. **按步骤显示进度**
   - 启动、重置、添加或更新智能体，界面上列出已经走过的步骤和每步用时，当前步骤下面显示细节：
     - 镜像构建：显示“第 k/N 步”和这一步最后一行输出，下载基础镜像时显示已下载多少；
     - 虚拟机启动：显示正在下载系统镜像、等待虚拟机就绪（1/3）、配置 Docker 等阶段。
   - 总量未知时不显示百分比。
   - 沙箱列表的每一行显示当前步骤，详情页和教程第 4 步显示完整步骤。
   - 进度最多每 0.3 秒推送一次，前端只更新对应的沙箱。原来每来一条进度，就把供应商、沙箱、MCP 和会话全部重读一遍。
2. **可以停止**
   - 启动、重置、添加或更新智能体都有“停止”按钮，后端新增 `CancelSandboxOperation`。
   - 镜像构建立即结束整个进程组。
   - 虚拟机启动这一段不打断，等它启动完成再停，因为中途结束 colima 可能损坏虚拟机。界面会说明正在等。
   - 添加或更新智能体：镜像构建好后才开始替换容器。从这一步起不能再停止，停止按钮也会隐藏，替换要么做完，要么恢复原沙箱。
   - 重置：拆除旧容器的阶段会做完，停止只跳过之后的重启。
   - 停止沙箱、删除沙箱、更新 MCP、更新开发环境不能中途停止。后两者也会显示进度，比如首次构建连接器镜像时；它们只是下发新设置，进行时不影响对话。
   - 停止后，按实际状态说明结果，比如“已停止启动；沙箱没有运行”，不会显示成成功。停止期间如果发生真正的失败，照实报告失败原因。失败结果会留在沙箱上，直到下一次操作。
3. **退出收尾**
   - 长操作的上下文都来自应用的根上下文，原来用的是 `context.Background()`。
   - 关窗口或按 Cmd+Q 时，如果还有操作在进行，先弹确认。选“停止并退出”后，窗口留着并显示“正在退出”，等这些操作停完才退出：构建立刻停止，虚拟机正在启动时要等它启动完成。
   - 等待期间不再接受新操作。再关一次窗口，会询问“继续等待”还是“立即退出”。
   - colima 的输出追加写进数据目录下的 `vm-start.log`，不经过应用的管道，所以即使立即退出，正在启动的虚拟机也会在后台启动完成，不会被打断。“停止运行环境”的 `colima stop` 同样写文件。
   - colima 的进程号记在 `vm-start.pid`。之后再启动时，如果这个进程还活着，并且确实是专用虚拟机的 colima 启动，就等它完成，期间显示它的日志，不会再启动一次。
   - 应用最后退出前还会再停一次所有操作，并等待收尾：正常退出最多 30 秒，选了立即退出最多 2 秒。
   - `cagectl`：第一次 Ctrl-C 停止当前操作，第二次立即退出。
4. **虚拟机只启动一次**：启动虚拟机加了跨进程的独占锁。两个沙箱同时首次启动时，后一个等前一个启动完，看到虚拟机已在运行就跳过。
5. **错误摘要**：外部命令的错误摘要按字符截断，不再截在汉字中间。

## 自动测试

- `internal/runtime`：
  - 命令输出逐行回调：遇到 `\r` 也分行，错误保留最后一行，取消时报“已取消”；
  - 摘要截断不切开汉字；
  - `docker build --progress=plain` 的步骤和输出解析；
  - colima 日志转成中文说明；
  - 虚拟机启动中收到停止，等 colima 正常结束后才返回；还没开始启动就收到停止，不会启动；
  - 两个启动同时进来，虚拟机只启动一次。
- 复查后补充：
  - `internal/runtime`：
    - 虚拟机启动的输出写进文件：子进程的标准输出是普通文件，不是管道；
    - 被取消的命令能识别为取消；
    - 镜像刚构建完时停止，不替换容器，也不记录新版本；
    - 重置在拆除阶段收到停止，拆除照常做完，不再重启。
  - `internal/service`：
    - 停止期间的真实失败照实报告；
    - 退出时不接受新操作；
    - 进入最后一步后不能再停止。
- `internal/service`：
  - 操作互斥且各页面都能看到步骤和细节；
  - 被停止的操作返回“已停止…”，记录为 stopped，不算成功；
  - 停止沙箱、删除沙箱不能中途停止，退出时会等它们做完；
  - 退出时停止所有能停的操作；
  - 进度细节限频推送，最后一条不会丢。
- 前端：用时格式、停止说明、结果文字。
- `make check`、`make test`（含竞态检查）、前端 `node --test` 都通过。

## 真机验证（2026-10-30，专用虚拟机）

- **构建停止**（`internal/runtime` 的 e2e 测试，`AIOFCAGE_E2E=1`）：
  - 用本机已有镜像做基础，构建一个第 3 步会执行 `sleep 300` 的镜像。
  - 第 3 步开始 3 秒后停止，构建 3.8 秒就返回“已取消”。
  - 停止前能在虚拟机里看到这一步的进程，停止后 5 秒内消失；宿主上没有 docker 构建进程，也没有留下镜像。
  - 进度依次显示“第 1/3 步：FROM …”“第 2/3 步：RUN echo first step · first step”“第 3/3 步：…”。
- **启动中停止、启动中退出**（`internal/service` 的 e2e 测试，`AIOFCAGE_PROGRESS_E2E=1`）：
  - 新建测试沙箱，把 Codex 固定为本机没有镜像的 0.150.0，启动时就得构建。
  - 构建走到安装 Codex 这一步后，分两次测：
    1. 停止：返回“已停止启动；沙箱没有运行”，记录为 stopped，沙箱没有运行；虚拟机里 `npm install @openai/codex@0.150.0` 的进程停止后消失；宿主上没有构建进程。
    2. 再启动一次，构建中走退出应用的收尾流程：结果相同。
  - 一共跑了三遍。第一遍停止后 5 秒，宿主上出现过一个命令行带构建临时目录的进程，之后就找不到了；后两遍都没再出现，没能确认它是什么。另外手动核对过：buildx 插件和 docker 在同一个进程组里，结束进程组后两者立即退出。
- **复查修复后**：两个真机测试都重跑通过，结果和之前相同。`cagectl sandbox events` 订阅时按一次 Ctrl-C，会打印提示并结束。
- **界面**：用模拟后端检查了：
  - 沙箱列表行：当前步骤、构建细节、用时和停止按钮；点停止会调用 `CancelSandboxOperation`，按钮变成不可点的“正在停止…”；
  - 详情页：步骤列表，含已完成步骤的用时和当前步骤的细节；
  - 已停止和失败的结果说明。
- **没有在真机上验证的**：
  - 虚拟机启动阶段的停止：要停掉正在使用的虚拟机才能测，会中断运行中的沙箱，只用假 colima 测了；
  - 桌面应用里的退出确认对话框：要在应用窗口里手动操作，请在演示前试一次。

## 复查

### 独立复查

请一个子代理只读复查，它报了 1 个高、2 个中、5 个低的问题，主要几条都写了测试复现。全部已修复：

| 问题 | 程度 | 处理 |
| --- | --- | --- |
| 退出等待中再关一次窗口，约 35 秒后应用直接退出。colima 的输出接在应用的管道上，应用退出后它下一次写日志就会死于 SIGPIPE，正好打断了要保护的虚拟机启动。`cagectl` 第一次 Ctrl-C 之后，后面的 Ctrl-C 全被吞掉 | 高 | colima 的输出改写进文件；再关窗口时询问继续等待还是立即退出；`cagectl` 第二次 Ctrl-C 立即退出 |
| 在替换容器或重置拆除阶段停止，沙箱会留在半拆状态。例如 Agent 停了、门卫还在；或者门卫已清空策略，提示却说沙箱仍在运行 | 中 | 替换容器从开始就做完，不能再停止；重置的拆除做完再停，只跳过重启 |
| 镜像刚构建完时停止，更新智能体会被记成成功，但运行中的容器还是旧镜像 | 中 | 镜像就绪后先检查停止请求；查不出容器状态时报错 |
| 请求停止之后发生的所有错误都报成“已停止”，真实原因丢失 | 低 | 只有停止导致的取消才算已停止 |
| 退出等待期间新开始的操作不会被停；环境锁的等待不响应停止 | 低 | 退出流程中拒绝新操作；锁的等待可以取消 |
| 前端刷新没有先后保护，旧响应可能盖住新进度 | 低 | 只采用最近一次刷新的结果 |
| 列表行在其他动作进行时显示旧的失败结果；更新 MCP 时看不到进度；教程里停止失败没有提示 | 低 | 已修正；更新 MCP、更新开发环境也登记为操作 |
| 停止落在查询虚拟机之后、启动 colima 之前，colima 仍会启动；操作超时也显示“已收到停止请求” | 低 | 启动 colima 前再检查一次；超时换一种说法 |

它还指出：Wails 退出时调用的 `[NSApp stop:]` 要等到下一个界面事件才生效。所以发出退出后 5 秒应用还在的话，会自行收尾并结束进程。这一条没有在真机上验证。

## 范围与限制

- **只做了两段**：项目复制导入的进度和取消、依赖安装、侧栏的全局“进行中”提示都没做。
- **没有字节进度**：虚拟机系统镜像由 colima 自己下载，拿不到字节数，只显示阶段和用时。
- **记录只在内存里**：重新打开应用后，看不到上次操作停在哪一步。
- **首次创建虚拟机时退出**：默认要等创建完成，最长 20 分钟；也可以选立即退出，让虚拟机在后台启动完成。这一点只做了单元测试：要在真机上测，得删掉正在使用的虚拟机。立即退出后，后台那个 colima 就没有超时限制了。
- **更新 MCP 的时限**：首次用数据库连接器时要构建镜像，超过 1 分钟仍会超时，这是原有的限制。
- **进度的格式**：构建进度靠解析 `--progress=plain` 的文本，Docker 改了输出格式时，只会退化成只显示步骤文字，不影响构建本身。
