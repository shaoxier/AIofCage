# 终端文件栏验证

[验收记录索引](README.md)

## 改动

对应第二轮会议第 4 条和 [todo 清单](../round2/todo.md)第 4 项的最小版本：终端右侧加一个只读的项目文件栏，可以浏览、预览文本、把路径插入当前会话。“变更”标签（Git 状态与 diff）、拖入路径、编辑都没做。

1. **面板**
   - 终端标签栏右端有“项目文件”按钮，可以展开或收起，按沙箱记住。
   - 窗口宽度不小于 1180 像素时，按记住的状态展开（没有记录就展开），固定宽 300 像素，放在终端右侧。
   - 窗口更窄时总是先收起，展开后浮在终端右侧，不挤占对话区。
2. **浏览**
   - 按需逐层读取，文件夹在前，再按名称排序。
   - 以“.”开头的条目默认不列，只显示“N 个隐藏项”，勾选“显示隐藏项”后列出。
   - 每层最多列 2000 个可见条目，隐藏项不占名额；一个文件夹最多读 2 万个条目，超出时提示“条目太多，只列出了一部分”。`node_modules` 这类目录只有点开时才读取。
   - 刷新方式：
     - 手动刷新；
     - 每轮对话结束时，自动重读已展开的文件夹和正在预览的文件，预览内容和滚动位置不会被清掉。
3. **预览**
   - 只读常规文件，最多 512 KB。
   - **文本**：UTF-8 文本按纯文本显示。超出 512 KB 的部分截掉，截断处不会切断汉字；单行超过 2000 字节的部分截掉（压缩过的代码、数据），并提示“过长的行已截断”。
   - **图片**：PNG、JPEG、GIF、WebP 按图片显示。先读出尺寸，超过 4096×4096 像素或读不出尺寸的不显示，因为几 KB 的文件就能声明一张界面解不动的大图。
   - **不读取内容的**：二进制文件、符号链接、管道和设备文件，只显示说明。
4. **插入路径**
   - 每一行和预览区都有“插入路径”按钮。没有打开的会话时按钮不可用。
   - **对话**：插入项目内的相对路径，插到输入框的光标处，前后自动补空格。
   - **Shell**：
     - 插入加了单引号的绝对路径，当作键入，不带回车。用户 `cd` 到别处也对，因为容器里项目的路径和宿主相同。
     - 以“-”或“+”开头的相对名称加“./”，免得被当成选项。
   - **不能插入或复制的文件名**：含控制字符（包括 C1 控制字符）、不可见的格式字符（双向排版控制、零宽字符）或行分隔符。
     - 控制字符会被终端当成按键或控制序列；
     - 格式字符能让看到的文件名和实际的不一样。
   - 另外可以复制路径，同样检查这些字符。
5. **布局与拖放**
   - 图片的粘贴和拖放只在左侧终端区域生效。
   - 拖到文件栏或标签栏上的文件也会被拦住，不会让窗口跳去显示那个文件。
6. **重绘**
   - 文件栏只在自身数据或会话状态变化时重绘，不随对话的流式输出整棵树重绘。
   - 终端页按沙箱重建，切换沙箱时不会留下上一个沙箱的预览。
7. **“在访达中打开”改为“在访达中显示”**：原来对项目路径直接执行 `open`，见下面的安全约束。

## 安全约束

项目里的文件都由 Agent 控制，所以：

- **读取限定在项目内**：
  - 打开项目目录时，从 `~/CageWorkspace` 开始逐级打开，每一级都不跟随链接、非阻塞、必须是文件夹。读取绑定在打开的那个文件夹上，之后路径被改名或替换也不会改变读的是哪里。
  - 原因：一个项目可以放在另一个沙箱的项目里面，外层沙箱的 Agent 能把内层项目换成链接或管道。`os.OpenRoot` 会跟随前者、卡在后者上。
  - 项目内部用 `os.OpenRoot` 的约束：指向项目外的符号链接和 `..` 都会被拒绝。
- **不跟随链接，不读特殊文件**：
  - 列目录和预览都先 `Lstat`：链接显示为链接，不进入也不读取。
  - 打开时都用非阻塞方式；列目录还要求打开的是文件夹，读文件要求打开后是常规文件。即使检查之后被换成管道，也不会卡住应用。
- **预览一律当纯文本显示**：不渲染 HTML、Markdown 或 SVG。SVG 按文本显示，不当图片。图片用 data URL 放进 `<img>`。
- **只读**：不在宿主上运行 git，不用其他程序打开项目里的文件，没有编辑、新建、重命名和删除。
- **“在访达中显示”**：
  - 改用 `open -R`，只在访达里选中项目文件夹，不打开它。
  - 原来直接 `open` 项目路径：如果项目被外层沙箱的 Agent 换成 `.app` 或 `.command`，点一下就会在宿主上运行。
  - 打开前还会按上面的方式确认项目目录。
- **不写日志**：文件路径和内容不写进审计日志。

## 自动测试

- `internal/service`，测试项目放在临时 `HOME` 下的 `CageWorkspace` 里，用到了这些“陷阱”：
  - 指向项目外私钥文件的链接、指向项目内目录的链接、`src/up → ../../..`；
  - 管道；
  - 含 `<script>` 的 Markdown 和 SVG；
  - PNG 头、含 NUL 的二进制文件；
  - 超过 512 KB 的多行汉字文本、单行很长的文件；
  - 名字里有反斜杠的文件夹和文件；
  - 隐藏文件；
  - 2001 个条目的 `node_modules`。

  覆盖的情形：
  - **列目录**：排序、隐藏项计数、链接和特殊文件的类型；超大目录在上限处截断；
  - **拒绝的路径**：`..`、绝对路径、绕出项目的链接、指向目录的链接；
  - **预览**：
    - 文本原样返回，交给页面当纯文本显示；SVG 不当图片；PNG 返回 data URL；二进制不返回内容；
    - 长文本在字符边界截断，长行被截短、其余行保留；
    - 反斜杠是普通字符；两种链接都不跟随；管道不读取，5 秒内返回；
    - 任何越界路径都读不到项目外的内容。
  - **嵌套项目被替换**：内层项目被换成指向工作区外的链接、换成管道、上一级目录被换成链接时，列目录不卡住、读不到外面的文件；已经打开的项目在路径被替换后仍读原来的文件夹。把逐级打开改回直接 `os.OpenRoot` 后，这个测试会失败。
  - **隐藏项**：2500 个隐藏文件不会挤掉 3 个可见文件。
  - **大图**：头部声明 20000×20000 的 PNG 不预览，64×64 的正常显示。
- 前端：
  - 在光标处插入并补空格；
  - Shell 引号，“-”和“+”开头的处理，绝对路径带空格时加引号；
  - 控制字符、C1 控制字符、双向排版控制符、零宽字符和行分隔符的检测。
- `make check`、`make test`（含竞态检查）、前端 `node --test` 都通过。

## 界面验证（模拟后端）

用内置浏览器检查（大多在 1400×860 窗口下）：

- **列表**：默认展开，列表顺序正确，显示“2 个隐藏项（以“.”开头）”；逐层展开 `src`、`src/util`。
- **预览**：
  - 含 `<script>` 和 `<img onerror>` 的 README 按纯文本显示，页面里没有生成任何 script 或 img 节点；
  - SVG 也按文本显示；PNG 显示为图片；
  - 二进制、链接只显示说明。
- **对话里插入**：
  - 没开会话时插入按钮不可用；
  - 开 Codex 对话后插入 `src/main.go`，输入框得到“src/main.go ”；
  - 把光标放在中间再插入 `README.md`，得到“src/main.go 和 README.md 看看”，光标停在插入内容之后。
- **Shell 里插入**：插入 `README.md` 发送“/Users/u/CageWorkspace/run/README.md ”，插入中文长文件名时整段加单引号。
- **控制字符**：文件名含换行的那一行，插入和复制按钮都不可用，提示原因。
- **自动刷新**：
  - 模拟一轮对话开始和结束，结束时自动重读三个已展开的文件夹，进行中不读；
  - 手动刷新和自动刷新时，预览没有清空，横向滚动位置保持不变。
- **对象内置名**：顶层文件夹叫 `constructor`，列表返回慢 300 毫秒，期间来了一条对话事件：页面没有报错，文件夹先显示“正在读取…”，再正常列出。
- **窄窗口**：1000×680 窗口下文件栏默认收起；展开后浮在终端右侧，终端区保持原宽度。
- **拖放**：拖到文件栏、标签栏上的文件被拦下；拖到左侧终端区显示“松开以添加图片”。合成的拖放事件改不了光标效果，真实效果要在桌面应用里看。
- **收起和长文件名**：收起后记为 `closed`，再展开记为 `open`；长文件名用省略号截断，悬停显示完整路径。

## 独立复查

请子代理在独立工作树里只读复查了一轮，用测试和模拟后端复现。没有高危问题，报了 3 个中、13 个低，另报了 1 个范围外的既有问题：

| 级别 | 问题 | 处理 |
|---|---|---|
| 中 | 列目录时，文件夹在检查后被换成管道，接口会永久卡住（原子交换约 6000 次复现一次） | 打开文件夹时加 `O_DIRECTORY` 和 `O_NONBLOCK` |
| 中 | 项目根目录本身不复核：项目放在另一个沙箱的项目里时，外层 Agent 把它换成链接就能读到项目外，换成管道则每次都卡住 | 从工作区开始逐级打开，每级不跟随链接、非阻塞，读取绑定在打开的文件夹上 |
| 中 | 顶层文件夹叫 `constructor`、`__proto__` 等对象内置名时，列表返回前一次重绘就会让终端页错乱 | 改用 `Map` |
| 低 | 每轮结束的自动刷新把预览滚回顶部 | 刷新时保留旧预览，新内容到了再替换 |
| 低 | “复制路径”不检查控制字符 | 和插入用同一个检查 |
| 低 | 只拦 C0 控制字符；“+”开头的名字没加“./” | 扩大到全部控制和格式字符；“+”开头也加“./” |
| 低 | 拖放处理收窄后，拖到文件栏或标签栏的文件会让窗口跳去显示那个文件（未复现） | 整个终端面板都拦下默认行为，只在左侧接收图片 |
| 低 | 最小窗口下记住的“展开”会把对话区挤没 | 窄窗口总是先收起，展开时浮在终端上 |
| 低 | 终端页被复用到另一个沙箱时，残留上一个沙箱的预览 | 终端页按沙箱重建 |
| 低 | Shell 插入的是相对路径，`cd` 到别处就不对 | Shell 改插绝对路径 |
| 低 | 每个流式事件都重绘整棵树 | 文件栏只在自身数据或会话状态变化时重绘 |
| 低 | 用了树形控件的语义却没有方向键导航；“隐藏项”文字有歧义 | 改用列表加展开按钮，`aria-expanded` 放在按钮上；改为“显示隐藏项” |
| 低 | 文件名含反斜杠时能列出、打不开 | 反斜杠按普通字符处理 |
| 低 | 隐藏项也占 2000 条上限，点文件多时一个可见文件都列不出 | 分批读取，隐藏项不占名额，单个文件夹最多读 2 万条 |
| 低 | 图片不限制像素尺寸（未复现） | 先读尺寸，超过 4096×4096 不显示 |
| 低 | 单行长度没有上限 | 单行超过 2000 字节截短 |
| 范围外（可能是高危，未复现） | “在访达中打开”直接对项目路径执行 `open`：项目嵌套时，外层 Agent 把内层项目换成 `.app` 或 `.command`，用户一点就会在宿主上运行 | 改用 `open -R` 只显示不打开，打开前先确认项目目录；按钮改名“在访达中显示” |

修复后没有再请子代理复查，逐条用上面的自动测试、变异验证和模拟界面确认。

## 范围与限制

- **没做的部分**：
  - “变更”标签：需要在容器里运行 git，不能在宿主上运行；
  - 拖入路径；
  - 拖宽面板；
  - 文件监听，目前只在每轮结束和手动刷新时更新；
  - 列表的方向键导航。
- **项目可以互相嵌套**：创建沙箱时没有禁止一个项目放在另一个沙箱的项目里。文件栏和“在访达中显示”已经防住了替换，但更根本的做法是创建时就禁止嵌套，留作后续。
- **沙箱停着且没有打开过会话时**，终端页只显示“启动沙箱”。读取本身不依赖沙箱运行，有已结束的标签时照常可以浏览。
- **列目录的排序**：每层只在读到的条目里排序，超过上限时不是全目录排序。
- **还没在真实桌面应用里试**：
  - 待试的部分：xterm 的 Shell 插入、真实拖放、virtiofs 下 Agent 新建的管道和链接在宿主上的样子；
  - 后端逻辑由上面的单元测试在真实的 macOS 文件系统上覆盖。
