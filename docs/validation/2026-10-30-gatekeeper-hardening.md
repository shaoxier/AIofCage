# 门卫与宿主凭据加固验证

[验收记录索引](README.md)

## 改动

对应[第二轮 todo 清单](../round2/todo.md)第四节排查出的问题。

1. **宿主请求不跟随跳转。** 连接测试、终端拉取模型、MCP 连接测试共用的客户端，以及 AI 解说的客户端，都不再跟随跳转（`internal/service/app.go`）。Go 跟随跳转时，会把 `X-Api-Key` 这类自定义请求头带到别的域名，也不拒绝从 https 降级到 http。连接测试遇到跳转时，提示用户检查接口地址。公开价格目录的请求不带凭据，仍然跟随跳转。
2. **预设 key 只能发往预设地址。** 预设里的钥匙串条目（比赛 key `sbx-builderday-key`）只能发往预设的 `xapi.qiniu.io`。
   - 保存供应商时校验（`internal/provider/provider.go` 的 `KeyRefAllowed`）。
   - 连接测试、终端拉取模型、AI 解说和启动沙箱下发密钥之前再各校验一次，防止此前已经保存的记录绕过。
   - 复制使用预设条目的供应商时，副本引用同一个条目，不再把 key 复制成一个之后可以改地址的新条目。
3. **key 用完即清零。** 连接测试和 AI 解说读出的 key，用完后从内存清零。
4. **门卫先解码、再脱敏错误正文。** 处理上游的 4xx 和 5xx 错误正文时（`internal/gatekeeper/redact.go`）：
   - gzip、deflate 先解压再替换；
   - br、zstd 等无法解码的编码，整段换成通用错误说明；
   - 除完整 key 外，还遮盖“`...` 加后四位”形式的回显，以及 key 的 SHA-256。LiteLLM 一类网关的报错会带这两项。
5. **泄露比对补全。** 隔离检查里“输出含真实凭据”这一项，加入了门卫管理 token、门卫到连接器的 token，以及 OAuth 凭据里的访问令牌、刷新令牌和客户端密钥。原来 OAuth 只比对整段 JSON，单独泄露出去的令牌比不出来。

## 自动测试

- `internal/provider`：预设条目只能用于预设域名；AIofCage 为供应商保存的 key 不受限制；任意钥匙串条目被拒绝。
- `internal/service`：
  - 改地址后保存被拒绝；
  - 绕过保存、直接改存储记录后，连接测试仍拒绝发送；
  - 复制供应商时引用原条目，不新增钥匙串条目；
  - 连接测试遇到 307 时不跟随，跳转目标没有收到请求；
  - OAuth 凭据拆开后进入泄露比对。
- `internal/gatekeeper`：
  - gzip 错误正文经过门卫后被解码，完整 key、“`...` 加后四位”和 SHA-256 都被遮盖；
  - br 正文被整段替换；
  - `readErrorBody`、`redactSecret` 的边界情况。
- `internal/runtime`：管理 token 和本沙箱连接器的 token 进入比对列表，名字相近的其他沙箱的 token 不进入。
- `make check`、`make test`（含竞态检查）通过。

## 真机验证（2026-10-30）

环境：专用 Colima profile `aiofcage`；Codex 0.164.0；供应商为七牛 xapi，模型 `gpt-6.1-sol`，比赛 key 存在钥匙串。任务按应用调用 Codex 的参数执行：用 shell 计算一个乘法，写入文件后回复结果。

- **修改前，已有的 Codex 沙箱**：退出码 0，用时 32 秒，结果正确。门卫记录两次 `POST xapi.qiniu.io /v1/responses`，都是注入 key 后完成的；Codex 自己访问 `chatgpt.com` 的请求被默认拒绝。此前的验收记录里，Codex 真实任务一直因 xapi 不可达而阻塞，这次补上了。
- **本分支构建的 cagectl，新建临时沙箱**：门卫镜像按新内容重建，下发策略时预设 key 的校验通过。同样的任务退出码 0，用时 20 秒，结果正确；门卫计 7 次请求、5 次拒绝，拒绝的都是 Codex 的遥测请求。验证结束后，临时沙箱和目录已删除。
- 没有在真机上让上游返回压缩的错误正文，这条路径由门卫的集成测试覆盖。

## 范围与限制

- 片段遮盖只覆盖 `...`、`…`、`***` 加后四位，以及十六进制 SHA-256，其他截断格式不在范围内。
- 只处理错误正文。成功响应（包括流式输出）里回流的 key 不检测。
- 无法解码的错误正文会丢掉上游原本的提示，agent 只能看到通用说明和状态码。
- agent 在没有绑定密钥的公共主机上自带凭据的问题，留到“开发环境”那项（开发源预设）一起处理。
- 已在运行的沙箱继续使用旧门卫，重启后才换成新门卫。
